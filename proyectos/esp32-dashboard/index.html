ESP32 · LoRa · Firebase

Enlace LoRa 915 MHz entre dos ESP32, API REST y dashboard web en producción.

Terminado · dashboard en producción

Ver repositorioAbrir en línea

Capturas

Captura de producción. Captura del dashboard desplegado en Firebase Hosting.

Contexto

Seminario en TIC, guía «Capa de red en IoT». Repositorio ESP32-Firebase-Dashboard.

Problema

Llevar lecturas de un sensor remoto hasta una interfaz web sin exponer credenciales administrativas en el microcontrolador.

Solución

El emisor envía por LoRa; el receptor publica por HTTP a una API que valida la clave X-API-Key y escribe con Admin SDK. Los clientes web solo pueden leer la colección lecturas.

Arquitectura

  • AM2301 → emisor (T3 V1.6.1) ── LoRa 915 MHz ──► receptor ── HTTP POST ──► API Flask ──► Firestore
  • Dashboard (Vite) lee Firestore en solo lectura y está desplegado en Firebase Hosting
  • Mensajes BLE desde un teléfono hacia el receptor; clave de API guardada en NVS, no en el código

Funcionalidades

  • Firmware de emisor y receptor que compilan con esp32 core 2.0.12
  • API REST con 30 pruebas pytest
  • Dashboard con 18 pruebas Vitest, build y despliegue
  • Reglas de Firestore: lectura pública de lecturas, escritura solo vía API

Aprendizajes técnicos

  • Diseñar las reglas de seguridad primero evitó poner credenciales de administrador en el microcontrolador.
  • Simular lecturas permitió probar la cadena completa sin depender del hardware.

Tecnologías

Pruebas y resultados

  • Extremo a extremo con lecturas simuladas: API → Firestore → dashboard
  • 30 pruebas pytest y 18 pruebas Vitest superadas
  • Dashboard publicado (HTTP 200)

Alcance y decisiones

  • La API se ejecuta en un PC del laboratorio (plan Spark, sin Cloud Run)
  • Las credenciales administrativas viven solo en la API, nunca en el microcontrolador
